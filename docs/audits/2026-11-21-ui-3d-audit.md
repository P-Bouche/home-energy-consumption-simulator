# UI & 3D Visual Audit — 2026-11-21

**Scope:** `apps/web` (React + MUI + React Three Fiber over `@hes/geometry`), audited end-to-end: DPE import → simulation → 2D editor → 3D viewer (heat-loss overlay on/off) → renovation scenarios.
**Method:** the app was run locally (`npm ci`; API `DATABASE_URL=memory:// npm run start -w apps/api` on :3000; `npm run dev -w apps/web` on :5173), the fixture `packages/open3cl-adapter/test/fixtures/2387E0888781I.xml` was imported through the real file input, the Open3CL simulation was run from the UI, one renovation scenario was created/simulated/compared, and every screen was captured in headless Chromium (SwiftShader software WebGL, viewport 1600×1000). Screenshots live in `docs/audits/assets/` and are referenced inline.
**Client evidence addressed:** (1) "style trop moderne mais moche / très peu utilisable", (2) "trop d'infos affichées", (3) "affichage 3D pas fidèle à une maison".

## 1. Design system / MUI theme usage

### F1 — Default MUI theme, zero design tokens (major)

**Evidence:** `assets/ui-01-upload-empty.png`, `assets/ui-04-simulation-result.png`, `assets/ui-09-scenario-comparison.png`. The app is stock MUI light mode: default blue `#1976d2` primary, purple `#9c27b0` secondary (visible on "Lancer la simulation"), all buttons rendered in uppercase ("CHOISIR UN FICHIER DPE…", "LANCER LA SIMULATION"), default 4 px radius everywhere except where overridden (see F12).

**Cause:** `apps/web/src/App.tsx:7` — `createTheme({ palette: { mode: 'light' } })`. No palette, typography, shape, spacing or component overrides anywhere in the app.

**Recommendation (mockup-level):**
- Define a real theme in one file: a restrained palette (e.g. deep slate/petrol primary instead of default blue, one accent for actions), `shape: { borderRadius: 10 }`, `typography.button: { textTransform: 'none' }` (French all-caps buttons read as aggressive), a type scale that differentiates `h4`/`h6`/`subtitle1`/`body2`/`caption` more strongly.
- Standardize surfaces: all panels the same elevation (either all `Paper` outlined with `p: 3`, or all elevated) — currently mixed (`ImportReportView`/`SimulationPanel`/`ScenarioPanel` use default-elevation `Paper p:3`, `BuildingEditorPanel.tsx:229` uses `variant="outlined" p:2`).
- One button hierarchy per screen: exactly one `contained` primary action, the rest `text`/`outlined`.

**Components:** `App.tsx`, all components under `apps/web/src/components/`, `pages/UploadPage.tsx`.

### F2 — Roboto declared but never loaded (minor)

**Evidence:** computed style on the upload page heading reports `fontFamily: "Roboto, Helvetica, Arial, sans-serif"` (`App.tsx` default theme) but no `@fontsource` import or `<link>` exists in `main.tsx` / `index.html`, so the app silently falls back to the OS font.

**Recommendation:** either bundle Roboto/Inter properly, or set the theme `fontFamily` to a realistic system stack. Pick one; today it is neither.

**Components:** `App.tsx` (theme), `apps/web/index.html`, `main.tsx`.

## 2. Layout & hierarchy — "trop d'infos affichées"

### F3 — One infinitely long page; every feature stacked after import (major)

**Evidence:** `assets/ui-03-import-report-full.png` — after a single import the page is a vertical stack of four large panels: import report → simulation → 2D editor → scenarios, all visible at once inside a narrow `Container maxWidth="md"` (`apps/web/src/pages/UploadPage.tsx:24`). The 3D viewer is the only "separate screen" (hash route), reached by a small outlined button.

**Recommendation:** turn the post-import page into a tabbed/stepper workspace (Import / Simulation / Éditeur 2D / Scénarios / Vue 3D) or a sidebar layout with the 3D viewer as the landing screen after import. Each screen then shows one dominant region instead of four. This is the single biggest lever on the "trop d'infos" complaint.

**Components:** `pages/UploadPage.tsx`, `App.tsx` (hash routing).

### F4 — Import report dumps raw XML paths in four unbounded lists (major)

**Evidence:** `assets/ui-02-import-report-top.png`, `assets/ui-03-import-report-full.png`. For the fixture: "Champs lus (125)", "Éléments non reconnus (418 chemins)", "Champs inférés (2)", "Champs absents" — each a dense `List` with XML paths (`dpe/administratif/diagnostiqueur/usr_logiciel_id`) as primary text and inline confidence `Chip`s (`ImportReportView.tsx:44-110`). The 418-path unrecognized list is pure noise for an end user.

**Recommendation:** collapse each section into an MUI `Accordion` showing only the count in the header; inside, show inferred fields as cards (value + source + confidence chip + date — this is the trust-critical part, make it prominent), show parsed fields as a searchable, paginated table, and summarize unrecognized fields ("418 chemins non reconnus — télécharger le détail" behind a download/copy action) instead of listing them.

**Components:** `components/ImportReportView.tsx`.

### F5 — Editor rows are chip+button overload; dialog exposes enum ids (minor)

**Evidence:** `assets/ui-06-editor-panel.png`, `assets/ui-07-edit-dialog.png`. Every element row is a `ListItem` with a full-width "Modifier" button plus two confidence chips (`BuildingEditorPanel.tsx:218-235`), in six stacked groups (Murs, Fenêtres, Toitures, Planchers, Chauffage, Ventilation) plus an audit trail of raw command tags (`building.wall.update.v1 · v3 · …`, `formatChange` renders `field : value [source, confiance x] → …`). The edit dialog asks for "Orientation (enum id)" as a free-text field prefilled with `"1"` (`KINDS` definitions, `BuildingEditorPanel.tsx:40-115`).

**Recommendation:** rows become compact tables (label + U + surface + one confidence dot), edit affordance is a row-hover icon button; the dialog uses `Select`s with human-readable labels for enum fields; the audit trail renders human sentences ("U du mur wall-1 : 1.9 → 0.3, par vous, 21/11/2026 12:56").

**Components:** `components/BuildingEditorPanel.tsx`.

### F6 — Scenario rows and comparison table: too many controls per row (minor)

**Evidence:** `assets/ui-08-scenario-empty.png`, `assets/ui-09-scenario-comparison.png`. Each scenario row stacks: name, "N commande(s)" chip, "version de base N" chip, energy/climate label chip, "Simuler" button, "Appliquer" green button, delete icon button (`ScenarioPanel.tsx:150-175`). The comparison table is a 9-column `size="small"` table (`ScenarioPanel.tsx:270-320`).

**Recommendation:** group row actions into a `Menu` (kebab) or icon buttons; move "version de base" into a tooltip; in the table, merge Énergie+Climat into one cell with two label chips, drop the Rang column into a sort order, and right-align deltas with green/red coloring.

**Components:** `components/ScenarioPanel.tsx`.

### F7 — Developer-facing raw data in the UI (minor)

**Evidence:** `assets/ui-05-simulation-raw.png` (raw Open3CL JSON in an 11 px `<pre>`, `SimulationPanel.tsx:76-81`), full building UUID as the viewer header title (`ViewerPage.tsx:30`, visible in `assets/ui-10-viewer-default.png`), `<code>{buildingId}</code>` in the simulation panel (`SimulationPanel.tsx:104`).

**Recommendation:** keep the raw JSON but behind a dialog with a copy button and syntax highlighting; replace UUIDs in titles with the DPE number / a building name fetched from the API, with the id in a tooltip or monospace caption.

**Components:** `SimulationPanel.tsx`, `ViewerPage.tsx`.

## 3. The 3D viewer

### F8 — Up-axis mismatch: the building is rendered "on its side" (major, visual-only fix)

**Evidence:** `assets/ui-10-viewer-default.png`, `assets/ui-14-viewer-heatloss-angle2.png` — the model reads as a squat frustum, not an upright house. Root cause: the domain geometry is **Z-up** (`COORDINATE_SYSTEM` in `packages/domain/src/geometry.ts:92-97`: `upAxis: 'Z'`) and `packages/geometry/src/three-adapter.ts` copies `vertex.z` straight into the three.js position attribute, but three.js/OrbitControls assume **Y-up** (`camera.up` probed as `(0,1,0)`). The camera placement in `ViewerPage.tsx:55-59` (`[max.x*1.6, -max.y*1.6, max.z*1.8]`) also derives the vertical component from the footprint depth (`max.y`), not from the height axis. Probe with the live camera: for bounds `max = (8.66, 6.53, 5.12)`, the roof center `(4.33, 3.27, 5.12)` projects to NDC y ≈ **+0.14**, while the far *ground* corner `(4.33, 6.53, 0)` projects to NDC y ≈ **+0.10** — the roof appears at the same screen height as the ground behind it, i.e. the building's height axis lies sideways on screen.

**Recommendation:** convert axes once at the rendering boundary (rotate the root group `rotation.x = -PI/2`, or map `(x,y,z) → (x,z,-y)` in `toThreeBufferGeometry`), then set a normal 3/4 perspective camera (e.g. azimuth 45°, elevation ~30°, distance ≈ 1.8× bounding sphere) and `OrbitControls` with default Y-up. No domain change needed — this is purely the `@hes/geometry/three` adapter + `ViewerPage` camera. After this fix the same box already reads as an upright building.

**Components:** `apps/web/src/pages/ViewerPage.tsx:53-60`, `packages/geometry/src/three-adapter.ts`, `packages/geometry/src/buffers.ts`.

### F9 — White void: no sky, ground, shadows, AO, or tone mapping (major)

**Evidence:** `assets/ui-10-viewer-default.png`, `assets/ui-13-viewer-heatloss.png`, `assets/ui-14-viewer-heatloss-angle2.png` — the model floats in a pure white void; no ground plane, no sky, no shadow under the building. Code: `<Canvas>` has no `gl`/`shadows`/tone-mapping config, scene has no background (`ViewerPage.tsx:62-70`); lighting is `ambientLight 0.75` + one `directionalLight 1.1` with `castShadow` never set; materials are flat `meshStandardMaterial vertexColors` with `DoubleSide` on all four layers (`BuildingModel.tsx:190-215`).

**Recommendation (mockup-level):** set `gl={{ antialias: true, shadowMap: { enabled: true, type: PCFSoftShadowMap } }}` + `dpr={[1, 2]}`, `flat={false}`, renderer `toneMapping = ACESFilmicToneMapping`, output sRGB (three r152+ default); scene background = vertical sky gradient (drei `Sky` or a large gradient `mesh`/CSS gradient behind a transparent canvas); add a ground plane (grass green `#7a8b5a`-ish, slightly rough) sized ~3× the footprint; one shadow-casting directional "sun" (warm, ~3-4 intensity with ACES) + hemisphere light (sky/ground colors); drei `ContactShadows` under the building for grounding. This alone transforms "floating box in void" into "building on a plot".

**Components:** `ViewerPage.tsx` (Canvas + lights), `BuildingModel.tsx` (materials, shadows on meshes).

### F10 — Heat-loss color scale is not normalized → the whole model turns green (major)

**Evidence:** `assets/ui-13-viewer-heatloss.png` vs `assets/ui-04-simulation-result.png`. The simulated building is label **G** (worst), yet with the overlay on, every visible face renders green/"faible perte". Cause: `colorForShare` (`apps/web/src/services/heat-loss.ts:57-68`) maps the **raw** share in [0,1] to green→amber→red, but shares are fractions of the *total* deperditions spread over ~11 envelope elements, so max share ≈ 0.2 → everything lands in the green third. The legend's red "forte perte" (`ViewerPage.tsx:67-69`) is unreachable in practice.

**Recommendation:** normalize in the presentation layer: map `share / maxShare` (or a percentile/log scale) onto the same green→red ramp, and show the numeric share in the tooltip on hover. Redesign the legend as a real gradient bar (MUI `Stack` + CSS `linear-gradient`) with min/max labels, instead of three disconnected 12×12 raw `<span>`s.

**Components:** `services/heat-loss.ts` (`colorForShare`), `ViewerPage.tsx:64-72` (legend), `components/BuildingModel.tsx` (`lossShareById`).

### F11 — Picking affordances are nearly invisible; materials are flat (minor)

**Evidence:** `assets/ui-11-viewer-hover.png`, `assets/ui-12-viewer-selected.png`. Hover only adds +0.12 to each RGB channel (`HOVERED_LIFT` in `services/view-colors.ts:34`); selection is a 50/50 mix toward blue (`view-colors.ts:36`). No emissive, no outline, no `cursor: pointer` on the canvas. The inferred layer uses a 16 px diagonal hatch texture (`BuildingModel.tsx:38-56`) that renders as loud orange stripes.

**Recommendation:** hover = emissive lift on the material (per-mesh material clone or `emissive` via color trick) + `cursor: pointer`; selection = outline (drei `Edges`/`LineSegments` in accent color around the element's faces, since picking is already per-element) + keep the color blend. Replace the hatch texture with a subtler pattern (thinner lines, lower contrast, or a solid semi-transparent amber with a small "inféré" badge in the legend only).

**Components:** `services/view-colors.ts`, `components/BuildingModel.tsx`.

### F12 — Viewer chrome: raw legend spans, UUID title, square side panel, always-on labels (minor)

**Evidence:** `assets/ui-10-viewer-default.png` (top bar: `h6` with full UUID, "← Import DPE" text button, switch, then three raw 12×12 `<span>` color squares with captions), `assets/ui-12-viewer-selected.png` (side panel `borderRadius: 0` while everything else is rounded; fields rendered as lowercase raw lines `id : wall-3`, `type : wall`, confidence embedded in sentence text, `ElementPanel.tsx:20-56`); `assets/ui-11-viewer-hover.png` (room label pill "Pièce principale (inféré)" and dark tooltip float over the model with no occlusion handling — `ViewerOverlays.tsx:24-64` projects every room label every frame regardless of visibility; tooltip is `whiteSpace: nowrap` so long labels overflow the canvas).

**Recommendation:** header becomes a real `AppBar`/`Toolbar` with the building's DPE number as title, the heat-loss switch as a labeled `ToggleButton`, and the legend as a compact gradient bar (see F10); side panel uses the theme radius, a definition-list layout with `Chip`s for mesuré/inféré and confidence color-coding; room labels get an occlusion test (raycast from camera to label position, hide if a wall is in front) or become toggleable, and tooltips get `maxWidth` + wrapping.

**Components:** `ViewerPage.tsx:29-72`, `components/ElementPanel.tsx`, `components/ViewerOverlays.tsx`, `components/BuildingModel.tsx` (`OverlayProjector`).

## 4. What the 3D model can and cannot express (visual vs geometry split)

The reconstruction (`packages/domain/src/reconstruction.ts`, catalog in `docs/geometry.md`) is deterministic and **the DPE gives areas, U-values, orientations — never coordinates**. Current model: rectangular footprint (4:3 aspect), one wall quad per DPE wall placed on the matching cardinal side, **flat** roof/floor slabs from the footprint, openings as **flat panels offset 0.05 m from the host wall** (not holes), rooms as translucent floor strips, `levelCount` supported for footprint area per level (default 1).

| Capability | Data available in DPE? | Where it lives | Class |
|---|---|---|---|
| Up-axis orientation, camera framing | n/a | three-adapter / ViewerPage | **visual** |
| Sky, ground, shadows, AO, tone mapping, materials | n/a | viewer only | **visual** |
| Heat-loss color normalization, legends, labels, picking affordances | n/a | viewer only | **visual** |
| Wall placement by orientation, areas → footprint size, wall thickness | yes (used) | `reconstruction.ts` | geometry (done) |
| Roof **slope** (gable/hipped) instead of flat slab | `roofType`/description exist but slope is not modeled | `reconstruction.ts` + `INFERENCE_RULES_VERSION` bump + meshHash change | geometry-level |
| Window/door **openings cut into walls** instead of overlay panels | yes (count, area, orientation, sill/height rules already inferred) | `reconstruction.ts buildOpenings` | geometry-level |
| Multi-level stacking of walls/rooms | `levelCount` exists, partially used | `reconstruction.ts computeFootprint` | geometry-level |
| Surroundings (terrain, neighbors, vegetation) | no | viewer-only set dressing | visual (fake) |

Conclusion: findings F8–F12 are fixable **without touching geometry**; "reads as a house" additionally needs the geometry-level items (pitched roof, real openings) listed in §6.

## 5. Quick wins (visual only, each ≤ 1 day, no geometry change)

1. **Fix the up-axis** in `three-adapter.ts` (or root-group rotation) + reframe camera from the bounding sphere → the building stands upright (F8).
2. **Scene dressing**: sky background color/gradient + ground plane + `ContactShadows` → no more white void (F9).
3. **Renderer setup**: `shadows` + PCFSoft, `ACESFilmicToneMapping`, hemisphere light instead of flat ambient → materials stop looking washed out (F9).
4. **Normalize the heat-loss ramp** (`share / maxShare`) + gradient legend → the overlay becomes informative and matches the G label (F10).
5. **Edge outlines** on envelope meshes (three `EdgesGeometry` or drei `Line`) → instant "house silhouette" readability (F9/F11).
6. **Theme tokens in `App.tsx`**: custom palette, `borderRadius: 10`, `button.textTransform: 'none'`, real font → kills the "default MUI" look (F1/F2).
7. **Tabs/stepper on the post-import page** instead of four stacked panels (F3).
8. **Accordions + counts** in the import report; unrecognized fields behind a "download detail" (F4).
9. **Viewer header cleanup**: DPE number instead of UUID, MUI legend, consistent `AppBar` (F12).
10. **Element panel restyle**: theme radius, definition list, confidence chips; occlusion-aware room labels; wrapping tooltips (F12).
11. **Stronger picking affordance**: emissive hover + selection outline + pointer cursor (F11).
12. **Human-readable editor**: enum fields as selects, audit trail as sentences, compact rows (F5).

## 6. 3D realism, graded by effort

**Class A — visual-only (viewer + three-adapter, no domain change, days):**
- Up-axis fix + cinematic default camera (45° azimuth / ~30° elevation, fit to bounding sphere), `minDistance`/`maxPolarAngle` limits so users can't go under the ground.
- Sky (drei `Sky` or gradient background), ground plane with subtle texture, soft shadows (PCFSoft + one warm directional "sun" + hemisphere fill), `ContactShadows`, ACES tone mapping.
- Material upgrade: per-kind `meshStandardMaterial` with roughness/metalness (walls: rough plaster tint; roof: darker, slightly rough; windows: glossy light-blue with `transmission`-like opacity; doors: wood brown), instead of flat vertex colors + `DoubleSide` everywhere. Keep vertex colors for the heat-loss layer only.
- Edge lines on the envelope; roof slab gets a slight parapet/overhang ring; compass/north indicator; scale bar.
- Heat-loss overlay: normalized ramp, gradient legend, hover tooltip with % share; inferred elements: subtle hatch or translucent amber (not loud stripes).

**Class B — geometry-level (requires `packages/domain/src/reconstruction.ts` changes + `INFERENCE_RULES_VERSION` bump + mesh-hash/contract tests + API/e2e updates, weeks):**
- **Pitched roof** (gable along the long axis, ridge height from `roofType`/default rule) instead of a flat slab — the single biggest "is it a house?" signal. Data exists (roof type/description); slope is currently not modeled.
- **Openings as real holes** in wall quads (subtract window/door rectangles at inferred sill/height) with a recessed frame, instead of floating panels at +0.05 m.
- Multi-level wall stacking from `levelCount` (footprint per level already computed) with floor slabs between levels.
- Wall thickness already 0.2 m — could extrude outward for a more solid look; chimney from heating-system data (speculative).
- Set dressing that fakes context without BIM data: lawn, a few trees (billboards), a simple fence, neighboring box volumes — purely viewer-side, but only *honest* if labeled as synthetic (confidence rule: never present inferred info as measured).

**Achievable fidelity statement:** within the current DPE-derived model, Class A gets the viewer from "floating frustum in a void" to "clean, grounded, correctly oriented massing model with readable heat losses" — an honest digital-twin look. "Looks like a photographed house" additionally requires Class B (roof shape, window openings, multi-level), which is geometry work with versioned inference-rule impact, not a visual pass.

## 7. Acceptance criteria for a follow-up design PR

- Post-import workspace is navigable (tabs/sidebar); no screen shows all four panels at once.
- Theme file defines palette/shape/typography; no uppercase buttons; loaded font.
- Import report sections collapsed with counts; inferred values always carry source + confidence + date in card form.
- 3D viewer: building upright (up-axis fix), grounded (shadow + ground), background non-white, heat-loss legend is a gradient with normalized scale, selection/hover affordances visible.
- No raw UUIDs, XML paths, enum ids, or command tags in primary UI text (details behind dialogs/downloads).

## Limitations & assumptions

- Screenshots were taken with SwiftShader software WebGL (no GPU in the sandbox); all findings are structural (layout, theme, axis math, color scales), but absolute shading quality on real GPUs may differ slightly.
- One fixture (`2387E0888781I.xml`, 5 walls / 4 windows / 2 doors / 2 roofs / 2 floors / 1 room, 7 inferred elements) was audited; larger multi-level DPEs may surface additional density issues in the editor lists.
- The heat-loss overlay was exercised against a label-G building; the all-green rendering (F10) is inferred from the raw-share color mapping plus the observed screenshot.
- This audit is docs-only by design: no code was changed.
